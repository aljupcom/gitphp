# GitPHP — دليل الأمان والصلاحيات وحماية الخادم 🛡️

> 📚 **الفهرس:** [فهرس الوثائق](README.md) • [التثبيت](installation.md) • [الرموز الشخصية (PAT)](token-push.md) • [واجهة REST API](api.md) • [إعداد SSH](ssh-setup.md)

---

صُممت منصة **GitPHP** وفق مبدأ **الدفاع المتعمق (Defense in Depth)** لتوفير أقصى درجات الأمان لعزل المستودعات، حماية الاعتماديات، ومنع التهديدات السيبرانية على مستوى التطبيق ونظام التشغيل.

---

## 1. نموذج الصلاحيات والأدوار (Access Control & RBAC)

تعتمد المنصة على نظام صلاحيات هرمي صارم يحدد إمكانيات المستخدمين بدقة:

| المستوى / الدور | استعراض الكود والملفات | استنساخ المستودع (Clone) | دفع التعديلات (Push) | إدارة الـ Issues و PRs | دمج طلبات السحب (Merge) | إعدادات المستودع والـ Webhooks |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| **زائر عام (Public)** | ✅ (في العام فقط) | ✅ (في العام فقط) | ❌ | ❌ | ❌ | ❌ |
| **متعاون قراءة (`read`)** | ✅ | ✅ | ❌ | ✅ (تعليق) | ❌ | ❌ |
| **متعاون كتابة (`write`)** | ✅ | ✅ | ✅ (غير المحمي) | ✅ (كامل) | ✅ (إذا اعتُمد) | ❌ |
| **مالك المستودع / المشرف (`admin`)**| ✅ | ✅ | ✅ (كامل) | ✅ (كامل) | ✅ (كامل) | ✅ (كامل مع الحذف) |

### أ) خصوصية المستودعات (Repository Visibility):
- **مستودع عام (Public):** متاح للجميع للقراءة والاستنساخ دون تسجيل دخول، ولكن عمليات الرفع (`push`) والتعديل تقتصر على المالك والمتعاونين بصلاحية `write`.
- **مستودع خاص (Private):** محجوب تماماً عن غير المصرح لهم؛ يرفض الخادم عمليات `clone` و `push` و API ما لم يتم تقديم بيانات اعتماد مالك أو متعاون مرخص.

## 2. حماية الفروع والوسوم وتدقيق الكود (Branch & Tag Protection)

تُنفَّذ قواعد حماية الفروع **والوسوم** برمجياً على مستوى الخادم عبر خطافات `pre-receive` لحمايتها سواء تم الرفع عبر الويب أو Git CLI:

1. **منع الحذف (Block Deletion):** حظر حذف الفروع الحساسة (مثل `main` أو `production`) أو الوسوم المحمية.
2. **منع الرفع القسري (Block Force-Push):** منع استبدال تاريخ الـ Commits بـ `git push --force` لضمان عدم فقدان أي كود، ويشمل ذلك **إعادة توجيه الوسوم القائمة** (tag re-pointing).
3. **أنماط مطابقة للمراجع (Ref Patterns):** كل قاعدة حماية تطابق اسم الفرز أو الوسم إما بالاسم الدقيق أو بنمط wildcard (مثل `v*` أو `release-*`).
4. **اشتراط مراجعة معتمدة (Require Approved Review):** تعطيل دمج أي Pull Request ما لم يحصل على موافقة (Approve) من مراجع مرخص.
5. **تجاوز المشرف (Admin Bypass):** خيار يتيح لمالك المستودع استثناء نفسه من القيود في الحالات الطارئة.

## 3. أمان المصادقة والاعتماديات (Authentication & Cryptography)

### أ) تشفير كلمات المرور (Argon2id):
- تُشفر جميع كلمات المرور الجديدة والمُعاد تعيينها باستخدام **Argon2id** (`PASSWORD_ARGON2ID` الصريح) المقاومة لهجمات المعالجات الرسومية (GPU / ASIC Attacks).
- الحسابات القديمة المُجزأة بـ bcrypt تظل قابلة للتحقق (`password_verify` يدعم كل الخوارزميات) وتُرحَّل تلقائياً إلى Argon2id عند أول تغيير كلمة مرور.

### б) المصادقة الثنائية (Two-Factor Authentication - 2FA):
- دعم كامل لتطبيقات TOTP القياسية (Google Authenticator, Microsoft Authenticator, 1Password).
- توليد مفاتيح احتياطية للطوارئ (Recovery Codes) تُخزن مجزأة.

### ج) الرموز الشخصية (Personal Access Tokens - PAT):
- توليد توكنات بصيغة `gtp_<hex40>` تمنح صلاحيات محددة (`read` أو `write`).
- تُخزن التوكنات في قاعدة البيانات عبر تجزئة **SHA-256** فقط (لا يمكن استرجاع التوكن الأصلي في حال اختراق قاعدة البيانات).
- إمكانية الإلغاء الفوري لأي رمز بنقرة واحدة دون التأثير على كلمة المرور الرئيسية.

## 4. أمان بيئة الخادم و محرك Git (Server-Level Hardening)

### أ) عزل مستخدم SSH (`git-shell-wrapper.php`):
- يمنع الغلاف الأمني مستخدم النظام `git` من فتح جلسة تفاعلية (No Interactive Shell).
- قصر الأوامر المسموحة حصراً على: `git-receive-pack`, `git-upload-pack`, `git-upload-archive`.
- عزل مفاتيح المستخدمين في ملف `~git/.ssh/authorized_keys` بقيود:
  `command="/path/to/wrapper",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty`

### ب) منع حقن الأوامر (Command Injection Prevention):
- تُستدعى أوامر Git عبر مصفوفات معاملات محددة (proc_open / Symfony Process) مع منع تنفيذ الـ Shell المباشر في جميع مسارات استعراض الكود والفحص.
- الاستثناء الوحيد المتبقي: تفريغ عامل الاستيراد الخلفي (import worker spawn) في `RepoImportController` حيث تُغلَّف كل القيم بـ `escapeshellcmd`/`escapeshellarg` ولا تحتوي أي مدخلات مستخدم خام.
- فحص وتطهير أسماء الفروع ومسارات الملفات عبر دالة `safeRef()` ومنع مسارات الرجوع `..` (Path Traversal).

### ج) أمان الجلسات وحماية ملفات الارتباط (Session Security):
- خصائص ملفات الارتباط: `HttpOnly=true`, `SameSite=Lax`, `Secure=true`.
- إعادة توليد معرف الجلسة `session_regenerate_id(true)` عند تسجيل الدخول لمنع هجمات Session Fixation.

## 5. سجل التدقيق الأمني (Audit Logs)

تقوم المنصة بتسجيل كافة العمليات الحساسة في جدول `audit_logs` متضمناً:
- عنوان الـ IP وهوية المستخدم وتاريخ العملية.
- نوع الحدث: تسجيل دخول، فشل مصادقة، إنشاء/إلغاء توكن، إضافة متعاون، تعديل حماية الفروع، حذف مستودع، أو تحديث الـ Webhooks.
- يمكن للمشرف مراجعة السجل من **Admin Dashboard → Audit Logs**.

## 6. فحص وتأمين بيئة الاستضافة (Checklist)

```bash
# 1. التحقق من صلاحيات الملفات والمفاتيح
php bin/fix-push.php

# 2. التأكد من حماية ملف الإعدادات
chmod 600 config/config.php

# 3. التأكد من حظر الوصول للملفات المخفية في Nginx / Apache
# Nginx: location ~ /\.(?!well-known).* { deny all; }
```
